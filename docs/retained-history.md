# Retained workspace history

The gateway records a bounded native timeline snapshot on a Retain workspace's own PVC before stopping a Ready workspace Pod. A metadata-only ConfigMap receipt names the immutable snapshot file and binds it to the workspace UID and residency generation. It reads that file for an authorized suspended or archived agent through a short-lived, credential-free Pod that mounts only the history directory of the exact UID-owned claim read-only. The reader has no ServiceAccount token or provider files. The chart installs a deny-all NetworkPolicy for readers; blocking packets requires a CNI that enforces that policy and remains part of live network qualification. Timeline content never enters gateway ConfigMaps or logs.

The snapshot keeps projected timeline pages only. Capture has a 60-second deadline and stores at most 100 agents, 1,000 projected entries and 2 MiB per agent, with an 8 MiB workspace cap. If an active timeline changes while older pages are fetched, only the first coherent tail page is retained and marked truncated. Missing agents and older pages beyond the cap return explicit unavailable/truncated errors. Canonical projection is unavailable while stopped. Each page is bound to the workspace UID and residency generation; the gateway rechecks the agent route, principal, resourceVersion, storage status and residency after the PVC read. A stopped read has a 45-second request deadline, including authority checks, and session closure cancels the helper path. Ephemeral or deleted storage cannot provide a transcript.

The gateway probes the actual running Pod for snapshot support. Old or custom images without the command continue to suspend with retained metadata, but uncached transcript pages remain unavailable. An already-suspended older workspace needs an explicitly authorized resume with a current image and subsequent suspend to create a snapshot; opening its agent never resumes it. Archive is terminal: an older archived workspace without a snapshot remains unavailable through this reader, and its retained PVC must not be adopted or its lifecycle rewritten to manufacture a migration. A failed or unready Pod may stop without a fresh snapshot, and an older generation's receipt is rejected. A Ready current-image Pod that fails snapshot capture keeps its compute and storage for inspection.

The helper Pod has a 90-second active deadline and is UID-deleted after each read. At most four read calls, including queued calls, are admitted per gateway process. Reads of the same workspace are serialized within the request deadline. A subsequent read waits for its exact owned, terminating helper to disappear and rechecks workspace and PVC identity before creating another. Cancelling a queued call does not let later calls overtake an active read. The gateway scans deterministic helper names after restart and every 30 seconds to delete readers older than two minutes; the workspace owner reference handles CR deletion. Reconciliation defers a workspace Pod restart or storage cleanup while a helper exists. Before writing, the gateway prunes files older than the latest committed metadata receipt. It prunes again after publication. Finalized files without a receipt, or newer than a supplied receipt, are never deleted by age: a pruning call cannot prove that an apparently unpublished file is not becoming the next committed cut. Abandoned temporary files older than ten minutes are removed. The writer caps a UID at 16 finalized files, so repeated failed captures cannot consume unbounded PVC space. If unproven files fill that budget, suspension fails closed and the files require operator inspection rather than automatic deletion. With `ReadWriteOnce`, the Kubernetes scheduler may briefly allow a read-only helper and a resumed writer Pod on the same node; immutable versioned snapshots and the gateway's final generation fence prevent a stale page from being returned. `ReadWriteOncePod` provides stricter mount exclusion when the storage class supports it.
