# Project source refs

The gateway handles `branch_suggestions_request` and `validate_branch_request` at an exact configured `/projects/<id>` path. It reads the configured repository with the Project's effective workspace image and Git credential profile in a disposable, Project-owned Pod. The Pod carries the standard workspace/component and credential-profile labels, so the configured workspace NetworkPolicy applies. It has no service-account token, user workspace record, persistent volume, provider credentials, or shared host checkout. The gateway reads only a bounded result from the Pod's termination message and deletes the Pod by UID. A durable run receipt precedes Pod creation; startup and periodic recovery remove expired orphan Pods after gateway replacement using the recorded UID, immutable run label, and Project owner UID. Existing `/workspaces/<id>` branch operations still go to that workspace's daemon.

Suggestions are a fresh remote-head observation for each request. They are filtered case-insensitively by query and sorted by name, with at most 20 rows. `committerDate: 0` means the remote advertisement did not provide a commit date. The read fails explicitly if the repository advertises more than 10,000 branches, emits more than 1 MiB of ref text, or the response would exceed the safe termination-message size; it does not report a partial inventory as complete. Git, Pod, queue, and RPC deadlines are bounded below the pinned client's 60-second request timeout. A maximum of two inspections run at once, with 16 short-lived waiting requests. Transport errors are returned as a static retry message without the URL, filesystem path, stderr, or credential material. HTTPS and the gateway's configured SSH forms use the same token or pinned-known-host projection as workspace initialization.

Validation uses Git's `check-ref-format --branch` and an exact remote-head lookup. It does not create a branch. A found branch returns `origin/<name>` with `isRemote: true`, matching the pinned protocol. A valid new name returns `exists: false`; an invalid name returns a fixed error. Project/profile UID and credential-reference fingerprints are checked again before results reach the caller. Inspection failures and changed authorization return a request error; no guessed branches are shown.

The Desktop picker sends a full tracking ref such as `refs/remotes/origin/feature/x`. A new workspace has a fresh checkout, so its initializer fetches the corresponding authoritative `refs/heads/feature/x` from origin, detaches at `FETCH_HEAD`, and creates the requested new branch. Desktop branch-off requests carry a `worktreeSlug`; if no explicit branch name is supplied, that slug becomes the branch name, matching the pinned daemon's creation behavior. This preserves the selected source commit at fetch time and avoids accidentally checking out the Project's configured default revision. The remote can advance between suggestion and creation; the picker is a live ref selection, not a commit pin. Programmatic SHA, tag, and pull-request creation remain separate supported paths. Forge search is not advertised or implemented by this feature.
