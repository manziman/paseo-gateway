# GUID agent identity contract (#64)

Paseo 0.9.1 and Desktop 0.9.2 join an existing-agent schedule to an agent by exact `agent.id === schedule.target.agentId`. The schedule target is a GUID; the old gateway exposed `workspace~base64(guid)` as the agent ID. The gateway now exposes the daemon's GUID for agents while retaining a durable, UID-bound reverse route. Workspace, project and terminal identities keep their existing translations.

## Durable identity

`AgentIdentityRegistry` stores `agent-route/<guid>` records with the exact backend GUID, workspace name and Kubernetes workspace UID. The record is created with compare-and-create before any GUID is published. Repeated claims from the same UID are idempotent. A claim for that GUID from another UID durably marks the record as a collision; neither identity can subsequently be published or routed. The gateway closes active client sessions on a locally detected collision so clients refetch a full directory. A stale entry already delivered before another replica's collision cannot be retracted without a reconnect, but every new inbound lookup reads the authoritative record and rejects a quarantined GUID. This deployment has one gateway replica; this design does not claim cross-replica immediate stream invalidation.

The route is never an authorization grant. Every inbound GUID or legacy `workspace~base64(guid)` ID must match a durable route and a currently authorized workspace with the same UID. Mutations also check residency, readiness, principal/token validity and UID after connection, upload and final durable route lookup. An unknown legacy alias fails closed. Route records, including failed-create reservations and collision tombstones, are retained after workspace/PVC garbage collection to prevent old IDs from rebinding to a later same-name workspace. This has an ongoing metadata cost; a future compact tombstone store may reduce it without discarding the identity history.

An `agent.create.request` without an explicit `agentId` receives a gateway-generated GUID reserved before the daemon mutation. If the caller supplies a GUID, the gateway first scans discoverable pre-upgrade inventories and claims them, then reserves the requested GUID. A duplicate is rejected before mutation without quarantining the existing agent. A Running workspace that is not Ready, a missing UID-bound retained inventory, or purged historical inventory prevents this *explicit-ID* backfill from proving uniqueness, so that request fails closed. Ordinary Desktop/CLI creates omit `agentId` and do not depend on unrelated workspace availability. A reservation remains a tombstone if the backend creation fails or the acknowledgment is lost; it cannot be reused because the outcome may be ambiguous. The idempotency journal still determines whether a keyed retry is observable or rejected, never replaying a dispatched mutation.

## Protocol boundaries

`AgentRouting` projects only schema-known agent routing metadata. It emits one GUID entry per native agent and accepts GUID and registered legacy IDs for direct fetch, commands, timeline subscriptions and forwarded mutations. User prompts, labels, environment, provider model metadata, runtime extras and output schemas remain opaque. The one reserved `paseo.parent-agent-id` label is normalized from an old scoped alias to its GUID for Desktop parent association; it does not authorize access to the parent workspace. Terminal IDs and workspace paths keep the original `translate` behavior.

Live and retained inventories are UID-bound before projection. The creation journal projects old scoped IDs on subscription updates, subscription snapshots and idempotent replay after authorizing the saved workspace UID; stored snapshots and receipts are not rewritten in place. Schedule targets remain the pinned GUID and continue to carry their stored target workspace UID. Existing-agent dispatch fetches the exact target and rechecks origin grant and target UID/status before sending the prompt. No prompt is retried after an ambiguous send.

Per-backend unsolicited events are projected and emitted through a bounded FIFO (256 frames, 16 MiB). Forwarded response projection and emission joins that FIFO after its network response arrives; network long-polls are not held in it. Page and retained-inventory projection use bounded concurrency. A fresh durable GET per public GUID projection prevents a cached positive claim from hiding a collision discovered elsewhere. Repeated GUIDs in one projected frame share that GET. The extra API reads are a deliberate correctness cost for this single-replica implementation and should be measured under production stream rates.

## Migration and verification

The gateway projects an entirely new directory generation; clients reconnect and refetch rather than merging old scoped and new GUID entries. Background best-effort backfill claims currently discoverable live/retained agents; outward projection also claims on read, so a missed backfill never becomes an unsafe route. Pre-upgrade unavailable inventory leaves old aliases unknown until that workspace can be inspected. Callers never replay an old prompt during cutover.

The regression suite covers durable claim/restart/collision, malformed routes, legacy aliases and UID fencing, the schedule GUID equality contract, provider metadata opacity, creation reservation and pre-upgrade journal replay, live and retained projection, ordered updates/replies, and post-await mutation fences. The unmodified Paseo 0.9.1 daemon Docker suite verifies production `WorkspaceOperations` and `CreationJournal` against two native workspaces: public GUIDs, legacy direct fetch, cross-Pod parent association, existing-agent schedule UID resolution, and gateway replacement with a seeded pre-upgrade scoped journal snapshot. Its SDK retry returns the GUID without a second daemon create. Transfer and terminal behavior also pass. Desktop existing-agent schedule association still requires manual qualification against a deployed gateway image after this change is merged.
